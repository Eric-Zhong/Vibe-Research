## 环境排障：Vibe-Research Windows 安装 Python 依赖

用户机器上安装 `.agents/skills/data-access/scripts/requirements.txt` 遇到两类坑，已定位：

1. **32 位 Python 陷阱**：本机默认 `python` 是 `Z:\Service\msys64\mingw32\bin\python.exe`（32 位 mingw，3.12.7）。用它建的 `.venv` 没有 `win_amd64` wheel，pandas/numpy 会退回源码编译并在 meson 阶段 `cannot find 'ld'` 失败；在 32 位下 pip 也会把「没有 32 位 wheel」报成 `conflicting dependencies`。
   - 可用的 64 位 CPython：`C:\Users\zhong\anaconda3\python.exe`（3.11.10 64bit）、`C:\Users\zhong\anaconda3\envs\comfyui\python.exe`（3.12.9 64bit）。无 `py` 启动器。
   - 已验证：在 64 位 3.11.10 / 3.12.9 上 `pip install --dry-run -r requirements.txt` 均可正常解析（akshare-1.19.3、mootdx-0.11.7、httpx-0.25.2 等），**无冲突**。
2. **setup-windows.ps1 被本地改过**：第 15 行 `.venv\bin\python.exe`（mingw posix 布局）应为仓库原值 `.venv\Scripts\python.exe`。该改动会让脚本在 Windows 上认为 venv 不存在、退回用 32 位 `python` 重建，需 `git checkout` 还原。
3. **pip 全局配置**：`C:\ProgramData\pip\pip.ini`（NVIDIA PyIndex 生成）含 `extra-index-url = https://pypi.ngc.nvidia.com`，该源在本机 SSL 握手失败会反复重试拖慢安装；另有 `no-cache-dir = true`。
4. **GBK 解码坑**：`requirements.txt` 首行中文注释在中文 Windows GBK locale 下会让 pip 抛 `UnicodeDecodeError: 'gbk'`；安装前 `set PYTHONUTF8=1` 可规避。

确定性修复路线：还原脚本 → `rmdir /s /q .venv` → `C:\Users\zhong\anaconda3\python.exe -m venv .venv` → `pip install -r requirements.txt --only-binary=:all:`（或跑 `scripts\setup-windows.cmd`，因 venv 已存在会跳过重建）。装完验证 `platform.architecture()[0] == '64bit'`。

## 代码修改：放开本地模式下模型地址用 HTTP 接入私有网关/本机推理

用户在「接入 AI」录入 `http://nas.yanhaohub.com:3002` 时报「远程模型地址必须使用 HTTPS」。根因：`orchestrator/src/providers.ts` 的 `providerUrlError` 只允许 loopback 的 HTTP。但 `runtime_provider.ts` 的 `assertHttp` 注释已说明本机产品应允许「私有网关/本机推理服务」。

改动：
- `providers.ts` 的 `providerUrlError(value, remote = false)`：新增 `remote` 形参。`remote=true`(远程分享模式) 维持严格 HTTPS + 仅 loopback HTTP；`remote=false`(本机模式) 允许任意 HTTP 指向私有网关/本机推理。模板校验 `validateProfile` 显式传 `remote=true` 保持严格。
- `runtime_provider.ts` 的 `assertHttp(u, remote)`：把 `VRA_REMOTE === "1"` 作为 remote 标志传入（在 `resolveRuntimeProvider` 算一次，模板覆盖与 `customEndpoint` 两处调用均透传）。

链路验证：`llmProbe` → `llmProbeCore`(`chat.ts:421` `resolveSelectedRuntime`) → `resolveRuntimeProvider` → `assertHttp` → `providerUrlError`，因此本机模式下自定义 OpenAI 兼容端点用 HTTP 现在可通过探针。远程模式仍强制 HTTPS。
`orchestrator` typecheck 通过；测试里 `doctor` 与「calc 端点参数键」两个失败是既有的、与本次改动无关。
