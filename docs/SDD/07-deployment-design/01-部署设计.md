# 07 · 部署设计（Deployment Design）

## 一句话定位
本地优先、可选远程；数据全在本地 `.local/`；端口冲突自动避让。

## 部署形态 1：本地模式（默认）
```bash
scripts/setup      # 建 .venv、装依赖、生成 .local/、跑体检
scripts/start      # 同时拉起本机 API 与页面，健康检查后开 http://127.0.0.1:5930
```
- 默认端口：页面 5930、API 8765；被占用/系统保留时**自动换空闲端口**并在终端说明（换页端口后浏览器设置按地址分开）。
- 固定端口：`--port` / `--api-port`（Windows `-Port`/`-ApiPort`）或 `VRA_UI_PORT`/`VRA_API_PORT`；指定端口不可用则直接报错。
- 提示"已有一个在运行"：直接开那个地址，别去抢端口。

## 部署形态 2：远程模式（云端个人 Agent）
```bash
scripts/start --remote --no-open --public-url https://<平台给5930的公网地址>
```
- 先打包页面（首次约半分钟），页面从 5930 对外；本机 API 仍只听回环，不对外。
- 远程模式页面端口**不自动换**：5930 被占就先停占用程序，或用 `--port` 换平台开放端口。
- 终端打印两行：本机打开地址 + "发给使用者的链接"（带 `?access=<口令>`）；首次打开后口令转成 HttpOnly cookie，地址栏口令被去掉，30 天内直开公网地址即可。
- **只用 https**：明文 http 会让用户 key 裸奔，启动器会对 http `--public-url` 警告。
- 页面只能挂根地址，不支持子路径。
- 口令在 `.local/access.token`（600）；换链接 `--rotate-access`；自管口令设 `VRA_ACCESS_TOKEN`。

## 免安装包
- Releases 下载免安装包（Windows x64 / Apple / Intel Mac），解压双击 `Start-VibeResearch`；数据在包内 `.local/`，升级=新包解压再把 `.local/` 复制过去。
- 包内 Node/Python 版本与下载地址只写在 `scripts/portable/runtimes.json`，升级运行时只改这一个文件。

## 版本检查
- 页面每天查一次 GitHub latest release；`VRA_UPDATE_CHECK=0` 完全不联网。
- 公开版本号优先读 GitHub latest release。

## 小结
部署设计的基调是"**数据不出本机 + 端口自动避让 + 远程才对外且强 https**"——把隐私风险压到最低。
