# 00 · 给小白的导读：怎么读这套 SDD 设计文档

> 这是 Vibe-Research 的**软件设计文档（SDD）**。DDD 讲"业务怎么划分"，这里讲"代码怎么搭、怎么跑"。

## SDD 和 DDD 的区别
- DDD：这套系统在"业务世界"里长什么样（限界上下文、实体、事件）。
- SDD：这套系统在"代码世界"里怎么实现（架构、模块、组件、数据、接口、安全、部署）。

建议顺序：**先 DDD 后 SDD**。DDD 让你懂"为什么这样分"，SDD 让你懂"具体怎么写、怎么跑"。

## 怎么读（01 → 07）
1. `01-architecture/` 总体架构——一张图看懂三层 + 编排器。
2. `02-module-design/` 模块设计——每个顶层文件夹是干嘛的。
3. `03-component-design/` 组件设计——关键类/函数怎么协作（受控工具、计算、合并）。
4. `04-data-design/` 数据设计——runDir 磁盘契约。
5. `05-interface-design/` 接口设计——MCP 工具、HTTP API、UI 接口。
6. `06-security-design/` 安全设计——凭据、隔离、隐私。
7. `07-deployment-design/` 部署设计——本地/远程怎么起。

## 一个贯穿全篇的事实
整套系统的"思考"由**可替换的大脑**完成（Claude/Codex/模型API），而产品提供**同一套受控工具 + 方法论 + 校验 + 合规闸门**。这就是"大脑可换、约束不变"的设计哲学——读任何一章都请带着它看。
