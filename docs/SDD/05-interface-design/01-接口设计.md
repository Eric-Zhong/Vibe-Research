# 05 · 接口设计（Interface Design）

## 一句话定位
系统对外的"门"有三道：大脑用的 MCP 工具、桌面用的 HTTP API、provider 用的模板接口。

## 接口 1：大脑的 5 个受控工具（MCP）
由 `run_tools.ts` 的 `TOOL_DEFS` 定义，经 `finance/run_tools_mcp.ts` 的 `buildRunToolsServer` 暴露：
| 工具 | 对应能力 |
|------|----------|
| `listRunFiles` | 列文件 |
| `readRunFile` | 读文件 |
| `runCalculation` | 确定性计算 |
| `writeStageOutput` | 写阶段产物 |
| `writeReport` | 写报告 |

大脑**没有** Shell/网络/任意文件读写——这是接口层最强的约束。

## 接口 2：本机 HTTP API（桌面 ↔ 编排器）
- 桌面 `desktop/lib/api.ts` 的 `api` 统一调用；后端契约在 `backend.ts`（`ApiError`、`ApiVerification`）。
- 模型对话流：`llm.ts` 的 `chatStream`；对话/研究的 Agent 入口在 `service.ts` 的 `guidedToolTurn` / `chat.ts` 的 `chatSend`。
- 页面端口默认 5930、API 默认 8765（冲突自动换）。

## 接口 3：provider 模板接口
- `providers/` 下 7 个 JSON 模板声明：端点、模型列表、环境变量。
- 安全规则（在 `runtime_provider.ts` 强制）：模板里的 `env_key` **不能**是 `VRA_*`（除运行 key 变量），也不能是取数用 key；key 只能进它自己的变量，不得改写基础环境。

## 接口 4：页面 ↔ 用户
- 浏览器里的模型 API key 只存 `localStorage`，随请求交本机后端，**不落盘、不进仓库/日志/测试夹具**（`AGENTS.md` §6.2）。

## 小结
三道门的共同主题：**最小暴露面 + 强校验**。MCP 把能力收窄到 5 个；HTTP API 走统一 `api` 层；provider 模板被代码强制防止越权读 key。
