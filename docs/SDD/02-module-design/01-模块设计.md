# 02 · 模块设计（Module Design）

## 一句话定位
顶层每个文件夹就是一个模块。下面逐个说它是谁、内部怎么组织。

## 模块清单（每个可单独成篇）
### 1. orchestrator/（六阶段研究编排器，TypeScript）
- `src/config.ts`：`Stage` 类型、阶段枚举。
- `src/registry.ts`：`buildStagePlan`、`regionOf`、`inScope`、`currentPlugin`——把研究计划从磁盘 plan 文件构建出来。
- `src/validator.ts`：`validateStage`、`StageOutput`——收工闸门。
- `src/schemas.ts`：所有 JSON 契约的 schema + 校验器（`manifestSchema`/`stageOutputSchema`/`fetchEnvelopeSchema`/`evidenceItemSchema`/`calcRecordSchema`）。
- `src/merge.ts`：合并取数账本、检测冲突、落盘 `evidence.json`/`calculations.json`/`conflicts.json`。
- `src/run_tools.ts` + `src/finance/run_tools_mcp.ts`：5 个受控工具的注册与 MCP server。
- `src/runtime_provider.ts`：解析"谁来想"（Claude/Codex/模型API）。
- `src/service.ts` / `src/chat.ts`：对外服务与对话。
- `src/engines/direct_stage_agent.ts`：直连引擎，把受控工具表交给大脑。

### 2. calc/（确定性计算库，Python）
- `contracts.py`：`validate_contract`、ARG_KINDS、FUNCTIONS——契约即"签名 + JSON 类型"，校验时不真跑公式。
- `cli.py`：`main`/`run`/`FUNCTIONS`（`chip_distribution`、`ttm_sum`、`ratio`…）——命令行入口。
- `SPEC.md`：函数契约权威说明。

### 3. desktop/（桌面 UI，React/TSX）
- `src/verticals/finance/lib/api.ts`：前端统一 `api` 调用层。
- `src/verticals/finance/lib/backend.ts`：`ApiError`、`ApiVerification`——后端契约与错误。
- `src/verticals/finance/lib/llm.ts`：`saveLlm`、`chatStream`——模型设置与对话流。
- `src/verticals/finance/lib/backtestView.ts`：回测结果视图模型（`BacktestView`/`Cell`/`ChartSeries`）。
- `vite-token.ts`：与编排器共用 `data_root` 找 API token。

### 4. backtest/（回测，Python，52 文件）
- 策略回测逻辑、多空辩论、归档。桌面侧 `BacktestCharts.tsx` 负责可视化。

### 5. providers/（模型接入模板）
- 7 个 JSON 模板 + README——声明端点、环境变量（key 只能进自己的 `env_key`，不许改写 `VRA_*`）。

### 6. .agents/skills/ 与 datasources/（取数与技能）
- `data-access/SKILL.md`：取数技能；`scripts/sources/indicators.py` 含 `calc_ma`/`calc_rsi` 等技术指标。

### 7. methodology/ 与 docs/（治理与文档）
- `constitution.md`：研究宪法（方法论、磁盘契约 §4）。

## 依赖主线
桌面 → 编排器 →（大脑 / calc / data-access / backtest）。Core 不反向依赖 finance 以外的业务。

## 小结
模块边界基本等于"职责边界"；跨模块只走 HTTP API / MCP / 磁盘契约，没有偷偷互相 import 业务细节。
