# 06 · 安全设计（Security Design）

## 一句话定位
这套系统最重要的安全设计，是"**把会思考的 AI 关进没有越权能力的沙箱**"，再加上凭据与隐私边界。

## 设计点 1：大脑隔离（最核心）
- 大脑没有 Shell、没有网络、没有任意文件读写（`AGENTS.md` §1）。
- 唯一通道是 5 个受控工具（见 `03-component-design`、`05-interface-design`）。
- 防腐层 `run_tools_mcp.ts` 把内部能力"翻译"成受限 MCP 工具，大脑看不到文件系统全貌。

## 设计点 2：凭据边界
- 本机 CLI 大脑（Claude/Codex/CodeBuddy）：用使用者自己登录；产品**不读、不存、不复制、不软链**任何登录文件，也不代填账号（`AGENTS.md` §6.2）。
- 模型 API key：只存浏览器 `localStorage`，随请求交后端，不落盘、不写仓库/配置/日志/测试夹具。
- 命令行研究的 key：从 provider 模板声明的环境变量读（如 `VRA_RUNTIME_API_KEY`），模板 `env_key` 被强制限制不能越权。

## 设计点 3：资料与引用边界
- 用户上传资料原文件只由服务层本机保存与解析；模型只收到**检索命中的正文片段**（`AGENTS.md` §6.1）。
- 联网不改变资料范围：不得把无关私人资料/密钥发给搜索服务。
- 用用户资料的回答必须保留真实引用 `[资料:<id> p.<页码>]`，漏引/错引必须拒绝。

## 设计点 4：远程模式约束
- 仅支持 https 公网；页面不能修改 WorkBuddy 位置；模型地址只收 https 公网域名，不能是 IP/localhost/内网名（`AGENTS.md` §3）。
- 访问口令存 `.local/access.token`（权限 600），30 天 cookie 续期。

## 设计点 5：发布前隐私检查
- 每次 push/tag/Release 前扫描工作树 + HEAD + 完整 Git 历史（不止 diff）；命中须人工核实（`AGENTS.md` §6.4）。
- `.local/`、`.env`、私钥、本机账号文件必须 ignored + untracked，且确认历史从未出现。

## 小结
安全不是事后加锁，而是**从架构上让危险动作根本不可能发生**（沙箱）+ **凭据永不落盘** + **发布前全量扫描**。
