# 04 · 数据设计（Data Design）

## 一句话定位
系统没有数据库，状态全写在 `runDir` 下的 JSON 文件里——这套约定叫"磁盘契约"。

## 一次研究运行（Run）的磁盘布局
```
<runDir>/
├─ manifest(.json)          研究范围与阶段定义（manifestSchema）
├─ stages/<stage>.json      各阶段产物（stageOutputSchema，status: complete/...）
├─ fetch/                   取数账本（FetchEnvelope；_开头为内部账本，跳过）
├─ calcs/                   确定性计算记录（CalcRecord）
├─ evidence.json            去重合并后的证据（EvidenceItem[]）
├─ calculations.json        计算记录汇总
├─ conflicts.json           { id_conflicts, source_conflicts }
└─ report                   最终长报告（上限约 10 万字符，不得为通过校验而截断）
```
> 权威定义见 `methodology/constitution.md` §4。

## 数据结构契约（在 `schemas.ts`）
- `manifestSchema()` / `validateManifest()`
- `stageOutputSchema(stage)` / `validateStageOutput(stage, d)`
- `fetchEnvelopeSchema()` / `validateFetchEnvelope(d)`
- `evidenceItemSchema()` / `validateEvidenceItem(d)`
- `calcRecordSchema` / `validateCalcRecord(d)`

## 合并与冲突语义（`merge.ts`）
- `mergeEvidence`：按 id 去重；同 id 不同 value → 记为 id 冲突（完整性错误）。
- `detectSourceConflicts`：同一数据源给出互相矛盾结论 → 记为 source 冲突。
- 冲突集每阶段刷新，供 risk/report 与 validator 核对。

## 私有数据落点
所有配置/产物/对话/台账/上传资料在 `.local/`，**已被 git 忽略**，不提交不打包（`AGENTS.md` §2、§6.4）。

## 报告长度约定
正文按长报告设计，当前上限约 10 万字符；不得为通过存储校验而截断已完成报告（`AGENTS.md` §6.1）。

## 小结
"文件即数据库"带来两个好处：① 研究过程可重放、可审计；② 隐私边界清晰（`.local/` 一把忽略）。这是数据设计的基石。
