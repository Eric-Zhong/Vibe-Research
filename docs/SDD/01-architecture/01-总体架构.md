# 01 · 总体架构与设计原则（Architecture）

## 一句话定位
本地运行的 A 股个股研究工作台 = **浏览器页面 + 本机服务 + 六阶段研究编排器 + Python 取数层 + 确定性计算库**。

## 架构分层（自顶向下）
```
┌─────────────────────────────────────┐
│ 浏览器页面（desktop/, React/TSX）      │  用户交互、对话、设置、报告展示
└───────────────┬─────────────────────┘
                │  HTTP API（localhost）
┌───────────────▼─────────────────────┐
│ 本机服务 / 编排器（orchestrator/, TS） │  调度、校验、收工检查、治理
│   ├─ 大脑解析 RuntimeProvider         │  决定"谁来想"
│   ├─ 受控工具 RunTools（5个, MCP）    │  大脑唯一能用的能力
│   ├─ 合并/校验 Merge/Validator        │  纪律闸门
└───────┬───────────────────┬─────────┘
        │                   │
┌───────▼──────┐    ┌────────▼────────┐
│ Python 取数层 │    │ 确定性计算库 calc │  （纯函数，同输入同输出）
│ data-access  │    │  （Python）       │
└──────────────┘    └─────────────────┘
```

## 关键设计原则（代码实证）
1. **大脑可换、约束不变**：大脑可以是 Claude/Codex/模型API（`runtime_provider.ts` 的 `resolveRuntimeProvider`），但无论换谁，受控工具、方法论、校验、合规 gate 是同一套（`AGENTS.md` §1）。
2. **垂类无关 Core**：`orchestrator/src/` 除 `src/finance/` 外不许出现行业词（纯净度测试会拦，`AGENTS.md` §5）。
3. **受控沙箱**：大脑没有 Shell/网络/任意文件读写，只有 5 个受控工具（`run_tools.ts` 的 `TOOL_DEFS`）。
4. **一切落盘可审计**：研究状态全在 `runDir` 下的 JSON 文件，可重放（`07-repositories`）。

## 启动入口
`orchestrator/src/startup.ts`（远程模式打包页面，API 只听回环）；页面端口默认 5930、API 默认 8765，冲突时自动换（`AGENTS.md` §2）。

## 小结
架构的灵魂是"**把不确定的'思考'关进受控沙箱，把确定的'计算/校验'留在产品里**"。理解了这点，后面每章都是它的展开。
