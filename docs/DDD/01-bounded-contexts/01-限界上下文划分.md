# 01 · 限界上下文划分（Bounded Contexts）

## 一句话定位
把一个大系统按"业务职责"切成一个个互不污染的小王国，每个王国内部用自己的语言把事说清楚。

## 小白怎么理解
想象一家研究所：有人专门**取数据**，有人专门**跑计算**，有人专门**写研究报告**，有人专门**做回测**。
每一摊活就是一个"限界上下文"。它们之间不直接改对方的私有数据，只通过约定好的接口交流。

## 本项目的上下文划分（代码实证）
| 上下文 | 职责 | 代码落点 |
|--------|------|----------|
| 研究编排上下文 | 六阶段研究流程、收工检查、产物校验 | `orchestrator/src/`（`orchestrate.ts`、`registry.ts`、`validator.ts`、`config.ts`） |
| 大脑/执行上下文 | 解析"谁来想"（Claude/Codex/模型API）、把受控工具交给大脑 | `orchestrator/src/runtime_provider.ts`、`service.ts`、`engines/direct_stage_agent.ts` |
| 受控工具上下文 | 大脑唯一能用的 5 个工具（列/读/算/写产物/写报告） | `orchestrator/src/run_tools.ts`（TOOL_DEFS）、`finance/run_tools_mcp.ts` |
| 确定性计算上下文 | 纯函数式计算，输入相同输出必相同 | `calc/`（Python，`contracts.py`、`cli.py`） |
| 取数上下文 | 调数据源、拉行情/财报 | `.agents/skills/data-access/`（`SKILL.md`、`scripts/sources/`） |
| 回测上下文 | 策略回测 + 多空辩论 + 归档 | `backtest/`、`desktop/src/verticals/finance/lib/backtestView.ts` |
| 桌面 UI 上下文 | 浏览器页面、对话、设置 | `desktop/`（React/TSX，`lib/api.ts`、`lib/backend.ts`） |
| 合规/治理上下文 | 研究宪法、方法论、SOP 约束 | `methodology/constitution.md`、`.agents/skills/` |

## 关键边界
- `orchestrator/src/` 除 `src/finance/` 外是**垂类无关 Core**，不能出现"股票/金融"等行业词（`AGENTS.md` §5）——这是 Core 与金融领域的硬性边界。
- 大脑上下文与编排上下文之间，只通过 **5 个受控工具** + 阶段产物文件 通信，绝不互通 Shell/网络。

## 小结
9 个上下文里，最核心的是"编排 + 受控工具 + 大脑"三者构成的"受控研究沙箱"。理解了它，整个项目就立住了。
