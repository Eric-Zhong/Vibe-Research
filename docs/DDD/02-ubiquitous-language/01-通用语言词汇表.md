# 02 · 通用语言词汇表（Ubiquitous Language）

## 一句话定位
团队和代码必须说"同一种话"。下面这些词在 DDD 讨论里含义固定，别混用。

## 核心术语（中英 + 业务含义 + 代码落点）
| 术语 | 含义 | 代码落点 |
|------|------|----------|
| 大脑 / Brain | 真正"思考"做研究的 AI（Claude/Codex/模型API），不是产品本身 | `runtime_provider.ts` 的 `ResolvedApiProvider`、`resolveRuntimeProvider` |
| 产品 / 工作台 | Vibe-Research 这个本地工具，负责调度与受控 | `service.ts`、`orchestrate.ts` |
| 阶段 / Stage | 六阶段研究流程中的某一环（如取数、计算、风险、报告） | `config.ts` 的 `Stage` 类型；`stages()` 枚举 |
| 阶段产物 / Stage Output | 每个阶段写出的 JSON 文件 | `schemas.ts` 的 `stageOutputSchema`、`validateStageOutput` |
| 受控工具 / Run Tools | 大脑唯一能用的 5 个工具 | `run_tools.ts` 的 `TOOL_DEFS`、`callRunTool` |
| 收工检查 | 阶段想结束时，校验产物是否齐、是否合规 | `validator.ts` 的 `validateStage`、`StageOutput` |
| 确定性计算 | 同输入必同输出的纯计算 | `calc/contracts.py` 的 `validate_contract` + `FUNCTIONS` |
| 账本 / Fetch Envelope | 取数动作的原始记录 | `schemas.ts` 的 `fetchEnvelopeSchema`、`merge.ts` 的 `loadFetch` |
| 证据 / Evidence | 去重合并后的取数结果 | `merge.ts` 的 `mergeEvidence`、`EvidenceItem` |
| 冲突 / Conflict | 同一 id 不同值 / 同源不同结论 | `merge.ts` 的 `detectSourceConflicts`、`conflicts.json` |
| 回测 / Backtest | 策略历史模拟 | `backtest/`、桌面 `backtestView.ts` |
| 多空辩论 / Debate | 多方观点对抗式研究 | `debate` 相关（`chat.ts` 的 `debate` 测试） |

## 易混淆辨析
- **大脑 ≠ 产品**：产品是壳，大脑是租来的"算例"；产品不读/不存/不复制大脑登录文件（`AGENTS.md` §6.2）。
- **Core ≠ finance**：`orchestrator/src/` 的 Core 是通用研究引擎，金融逻辑只在 `src/finance/`。

## 小结
读后续文档时，用这张表对号入座，避免"同一个词各说各话"。
