# 08 · 领域事件（Domain Events）

## 一句话定位
"已经发生过的业务事实"——跨聚合、跨上下文传递消息用，而不是改数据用。

## 小白怎么理解
比如"某阶段收工了""回测跑完了"。这些不是命令（去改东西），而是**通知**（告诉别处：事情发生了）。

## 本项目的领域事件（按代码与规则推断）
| 事件 | 触发时机 | 落点 / 消费者 |
|------|----------|---------------|
| 阶段完成 StageCompleted | 某阶段通过收工检查 | 编排器推进下一阶段（`orchestrate.ts`）；validator 放行 |
| 取数完成 FetchRecorded | 一次受控"计算/取数"写入账本 | `merge.ts` 合并成证据 |
| 冲突产生 ConflictsDetected | 合并时发现 id/源冲突 | risk / report 阶段与 validator 核对（`conflicts.json`） |
| 回测/辩论完成 Archived | 回测或辩论完成或部分完成 | 自动写入用户本地记录（`AGENTS.md` §6.1） |
| 报告生成 ReportWritten | 报告写好 | 桌面页面留档 `.local/chat-web/` |

## 实现特点
本项目没有显式的"事件总线"，而是用**文件落地 + 后续阶段读取**来表达事件：
- 上一阶段写文件（= 发出事件）；
- 下一阶段读文件（= 消费事件）。
这是一种"**基于磁盘的隐式事件**"，简单、可重放、天然持久化。

## 归档纪律（来自规则）
回测与多空辩论完成/部分完成后**自动写入本地记录**；多空辩论归档必须保存"每阶段数字复核摘要及全部算式错误明细"；中止后重开不得让旧会话回调污染新会话（`AGENTS.md` §6.1）。

## 小结
"文件即事件"是本项目对领域事件的务实实现——没有中间件，靠磁盘契约串联全流程。
