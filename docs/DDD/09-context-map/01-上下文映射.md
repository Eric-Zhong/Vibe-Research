# 09 · 上下文映射（Context Map）

## 一句话定位
把各个限界上下文之间"怎么连、谁听谁的"画出来——这是 DDD 战略设计的收尾图。

## 小白怎么理解
前面切了 9 块（01 章）。现在画连线：谁调谁、谁给谁发消息、有没有"翻译层"防止互相污染。

## 本项目的上下文关系
```
[桌面UI] ──HTTP API──▶ [编排器 Core]
                              │
                              ├─调用─▶ [大脑/执行] (解析 Claude/Codex/模型API)
                              │            │
                              │            └─提供─▶ [受控工具] (5个, 经 MCP 给大脑)
                              │
                              ├─调用─▶ [确定性计算] (calc/, 纯函数)
                              ├─调用─▶ [取数] (.agents/skills/data-access)
                              ├─调用─▶ [回测] (backtest/ + 桌面 backtestView)
                              └─受─▶ [合规/治理] (methodology/constitution.md 约束流程)
```

## 关键关系类型（DDD 术语对照）
- **防腐层（ACL）**：`run_tools_mcp.ts` 的 `buildRunToolsServer` 把内部能力包成 MCP 工具交给大脑，大脑只看到 5 个工具，**绝看不到** Shell/文件系统全貌——这就是隔离大脑的"防腐层"。
- **遵奉者（Conformist）**：桌面 UI 遵奉编排器定义的 HTTP API / 数据契约（`desktop/lib/backend.ts` 的 `ApiError`、`ApiVerification`）。
- **共享内核（Shared Kernel）**：`orchestrator/src` 的 Core 被桌面（`vite-token.ts` 的 `apiTokenPath` 共用 `data_root.ts`）与编排器共享，但只共享"配置/数据根"，不含业务逻辑。
- **客户-供应商**：页面是客户，本机 API 是供应商（`desktop/lib/api.ts` 的 `api` 调用后端）。

## 最特殊的约束
大脑与产品之间**只有 5 个受控工具 + 阶段产物文件**两条通道，没有别的（`AGENTS.md` §1）。这是整个上下文映射里最核心的"防火墙"。

## 小结
9 个上下文靠"HTTP API + MCP 受控工具 + 磁盘契约文件"三件套连起来；其中 MCP 防腐层保证了"聪明的大脑"无法越界——这是本项目架构灵魂的最后一笔。
