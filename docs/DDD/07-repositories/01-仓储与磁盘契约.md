# 07 · 仓储（Repositories）与磁盘契约

## 一句话定位
领域对象"存到哪、怎么拿出来"——DDD 只关心**接口**，不关心底层是文件还是数据库。本项目底层就是**文件**。

## 小白怎么理解
别的系统用数据库当仓库；本项目把"研究运行的全部状态"写成 `runDir` 下的 JSON 文件。仓储 = 这些文件的读写约定，叫"磁盘契约"。

## 仓储接口与落点
- **取数账本仓储**：`merge.ts` 的 `loadFetch(runDir)`——扫 `fetch/` 目录，跳过 `_` 开头的内账本文件。
- **计算记录仓储**：`merge.ts` 的 `loadCalcs(runDir)`——扫 `calcs/` 目录。
- **证据/计算/冲突仓储（写）**：`writeMergedArtifacts` 落盘 `evidence.json` / `calculations.json` / `conflicts.json`。
- **阶段产物仓储**：`run_tools.ts` 的 `writeStageOutput`（受控工具之一，写到 `stages/<stage>.json`）+ `schemas.ts` 的 `validateStageOutput`。
- **报告仓储**：`run_tools.ts` 的 `writeReport`。

## 磁盘契约（权威定义见 `methodology/constitution.md` §4）
每个 Run 在 `runDir` 下至少有：`manifest`、各 `stages/<stage>.json`、`fetch/`、`calcs/`、`evidence.json`、`calculations.json`、`conflicts.json`、`report`。

## 隐私与落点
所有私有数据在 `.local/`（已被 git 忽略），**不提交、不打包、不发第三方**（`AGENTS.md` §2）。仓储的"库"就是 `.local/` 下的运行目录。

## 小结
本项目的"数据库"是文件系统，仓储即"按契约读写 JSON 的纯函数"。这让研究过程**完全可审计、可重放**——这是 DDD 理想中"仓储隔离领域与存储"的朴素实现。
