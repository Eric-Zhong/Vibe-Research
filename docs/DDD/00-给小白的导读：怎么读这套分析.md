# 00 · 给小白的导读：怎么读这套 DDD 分析

> 这是 Vibe-Research 项目的**领域驱动设计（DDD）**分析。写给第一次看这套代码的人。

## 什么是 DDD，为什么要看它
DDD 不是教你写代码，而是帮你**把"业务长什么样"想清楚**：
- 这个系统到底解决谁的什么问题？
- 业务能被切成哪几块（每个块叫一个"限界上下文"）？
- 每个块里有哪些核心概念（实体、值对象、领域服务）？
- 它们怎么互相说话（领域事件、上下文映射）？

**一句话**：DDD 看"世界怎么划分"，SDD（旁边的文件夹）看"代码怎么搭"。先看 DDD，再看 SDD，逻辑就顺了。

## 怎么读（按编号从 01 看到 09）
1. `01-bounded-contexts/` 先看——系统被切成哪几块。
2. `02-ubiquitous-language/` 记术语——同一个词在不同地方意思可能不同。
3. `03-domain-model/` ~ `06-` 是"战术设计"：领域模型、聚合、值对象、领域服务。
4. `07-repositories/` 数据怎么存（注意：这里说的是"抽象"，不是具体数据库）。
5. `08-domain-events/` 业务事实怎么跨块传递。
6. `09-context-map/` 最后看——各块之间怎么连起来。

## 一个最重要的前提（来自项目规则）
这套系统的"大脑"（做研究的 AI）**没有 Shell、没有网络、没有任意文件读写**，它只能通过 **5 个受控工具**做事：
列文件、读文件、确定性计算、写阶段产物、写报告。
所以 DDD 里所有"领域行为"都要映射到这 5 个工具上——这是本项目最特别的设计约束，请牢记。
