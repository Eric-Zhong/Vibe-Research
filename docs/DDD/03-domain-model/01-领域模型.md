# 03 · 领域模型（Domain Model）

## 一句话定位
把"研究一次"这件事，画成一组核心概念及其关系。

## 小白怎么理解
一次研究 = 一个 **Run（研究运行）**，它下面挂着：
- 一个 **Manifest（清单）**：这次研究要干啥、分几阶段。
- 若干 **Stage（阶段）**，每个阶段产出 **StageOutput（阶段产物）**。
- 一堆 **Fetch（取数账本）** → 合并成 **Evidence（证据）** 和 **Calc（计算记录）**。
- 最终汇成一份 **Report（报告）**。

## 核心模型与代码落点
- **Run / 研究运行**：由 `runDir`（运行目录）贯穿全程；`merge.ts` 的 `writeMergedArtifacts(cfg: RunConfig)` 以 `runDir` 为根读写。
- **Manifest**：`schemas.ts` 的 `manifestSchema()`、`validateManifest()`——定义研究范围与阶段。
- **Stage / StageOutput**：`config.ts` 的 `Stage`；`schemas.ts` 的 `stageOutputSchema(stage)` 规定每阶段必填项（含 `status` 枚举：complete/incomplete/skipped/failed）。
- **Fetch → Evidence → Calc**：`merge.ts` 的 `loadFetch`/`mergeEvidence`/`loadCalcs`；`schemas.ts` 的 `fetchEnvelopeSchema`/`evidenceItemSchema`/`calcRecordSchema`。
- **Conflict**：`merge.ts` 的 `detectSourceConflicts` 产出 `conflicts.json`。

## 关系（用一句话串起来）
Manifest 定调 → 各 Stage 在受控工具约束下产出 StageOutput → 取数账本经 merge 变成 Evidence/Calc → 校验（validator）→ 冲突检测 → 汇总成 Report。

## 小结
这个模型的关键词是"**一切落到 runDir 下的文件**"——领域状态靠磁盘契约表达，而非内存对象。这正是本项目"受控、可审计"的根基（详见 `07-repositories`）。
