# 05 · 值对象（Value Objects）

## 一句话定位
"没名字、不可变"的概念——两个值对象只要内容一样，就是同一个；改了就生成新的。

## 小白怎么理解
比如"一段取数结果""一个时间区间""一条计算记录"。它们不是"某只股票的档案"（那是实体，有唯一 ID），而是"一次算出来的数值包"。

## 本项目的值对象
| 值对象 | 说明 | 代码落点 |
|--------|------|----------|
| `FetchEnvelope` | 一次取数动作的原始账本（含 script、返回数据） | `schemas.ts` 的 `fetchEnvelopeSchema`、`loadFetch` |
| `EvidenceItem` | 去重后的单条证据 | `merge.ts` 的 `mergeEvidence`、`evidenceItemSchema` |
| `CalcRecord` | 一条确定性计算记录（算式 + 值） | `schemas.ts` 的 `calcRecordSchema`、`validateCalcRecord` |
| `SourceConflict` | 同源不同结论的冲突描述 | `merge.ts` 的 `detectSourceConflicts` |
| `Cell` / `ChartSeries` | 回测展示用的数值单元/序列（不可变展示数据） | 桌面 `backtestView.ts` 的 `Cell`、`ChartSeries` |
| `Num` | 带状态的数字（ok/缺失/原因），不是裸 number | 桌面 `earningsBrief.ts` 的 `Num` 类型 |

## 为什么是值对象而非实体
- 它们**没有业务标识**：不存在"这是 1 号证据、那是 2 号证据"的稳定主键，靠内容判定相等。
- 它们**不可变**：一旦产生就当作事实封存（`runDir` 下文件即快照），不会"原地修改"。

## 小结
值对象在 DDD 里是"用完了就信"的事实包；本项目把它们落盘成 JSON 文件，天然符合"不可变事实"的语义。
