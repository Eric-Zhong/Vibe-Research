# 领域驱动设计（DDD）分析

本目录用于存放对 Vibe-Research 整体项目的**领域驱动设计**分析。

DDD 关注「业务领域」本身：领域如何被切分为多个**限界上下文（Bounded Context）**，
各上下文内的**通用语言（Ubiquitous Language）**、领域模型、聚合、值对象、领域服务、
仓储与领域事件，以及上下文之间的**上下文映射（Context Map）**。

> 本项目是本地运行的 A 股个股研究工作台，涉及：研究编排器、取数层、确定性计算库、
> 回测、模型接入、桌面 UI、Agent 大脑集成等。分析时应先用 DDD 视角识别领域边界，
> 再用 SDD 视角补充技术实现设计。

## 目录结构（按常规阅读顺序）

| 序号 | 目录 | 用途 |
|------|------|------|
| 01 | `01-bounded-contexts/` | 限界上下文划分与各上下文职责边界（战略设计起点） |
| 02 | `02-ubiquitous-language/` | 通用语言词汇表（中英术语对照与业务含义） |
| 03 | `03-domain-model/` | 领域模型、核心概念及其关系 |
| 04 | `04-aggregates/` | 聚合根、实体与聚合内一致性边界 |
| 05 | `05-value-objects/` | 值对象（不可变、无标识的领域概念） |
| 06 | `06-domain-services/` | 领域服务（无法归到单一实体的领域行为） |
| 07 | `07-repositories/` | 仓储（领域对象的持久化与检索抽象） |
| 08 | `08-domain-events/` | 领域事件（跨聚合/上下文的业务事实） |
| 09 | `09-context-map/` | 上下文映射（上下文关系、集成方式，战略设计收尾） |

## 小白从这里开始
先读 **`00-给小白的导读：怎么读这套分析.md`**，再按 `01-` ~ `09-` 子目录顺序看。每个子目录里有两篇编号文件：
- `01-*.md`：**小白版**，用大白话讲"这个 DDD 概念是什么、代码长啥样"。
- `02-架构师视角：为什么这样设计.md`：**架构师版**，讲"作者为什么这么设计、借鉴了谁、用了什么设计模式"——想进阶就接着读它。

建议读法：先通读全部 `01-`，再回看感兴趣的 `02-`。
